# 架构师模式

这是个人启动入口。公共规则和项目索引由管理仓库维护，具体项目在各自仓库工作。

1. 读取 [管理仓库配置](references/project.json)，定位管理仓库的现有克隆并核对远程。配置路径不存在时，先在可用项目记录中查找同一远程；仍找不到时在允许的工作目录独立克隆，保留已有目录内容。
2. 同步管理仓库，读取其 `AGENTS.md`、配置指定的 `project_protocol` 和 `registry_path`。按多项目管理规则选择目标：优先用户明确指定的仓库或项目，其次本会话已确认的项目；独立新项目先立项，已有项目的新功能留在原仓库。管理仓库自身的规则和工具维护使用管理仓库。
3. 只要求启动模式且目标未确定时，加载索引后简要报告可选项目或空索引，邀请用户描述需求。项目含糊时集中澄清，继续不依赖选择的整理工作；不自动把业务需求放进管理仓库。
4. 确定目标后，按仓库身份定位或准备克隆，读取该项目 `AGENTS.md`、`architect_entrypoint` 及其要求的配置和协作协议。新项目由架构师在首个编码任务发布前准备独立仓库和协作文件。命令显式指定目标仓库工作目录，当前聊天原来的工作目录无需改变。
5. 在项目仓库同步 Git、检查任务并恢复工作。需求、设计、任务、代码和审查遵循该项目协议；交接注明项目名称、仓库地址、任务与实际提交。用户同时给出了需求时立即推进。

使用当前会话的文件、网络和认证权限。权限或同步失败时明确记录实际状态，继续不受影响的工作，不把本地进度说成已远程交接。
