# F0001：以 Git 驱动架构与编码 Agent 协作

## 目标与参与者

人类持续提出功能，由架构师形成规格并审查，由另一模型编码，实现可跨模型、可恢复、可追溯的顺序协作。当前交付是协作框架；业务功能由后续需求建立任务。

## 需求与验收

| 需求 | 行为 | 验收 |
| --- | --- | --- |
| REQ-01 | 架构师负责需求、设计、拆解和审查 | AC-01：提供可独立读取的架构师入口、技能和输出模板 |
| REQ-02 | 编码模型可从 Git 获取全部任务上下文 | AC-02：提供厂商无关的编码入口，任务能绑定规格提交和路径 |
| REQ-03 | 所有交接进入 Git | AC-03：发布、领取、送审、返工、验收均定义提交及推送顺序 |
| REQ-04 | 实现与控制分离 | AC-04：定义控制分支状态、任务分支代码及竞争领取规则 |
| REQ-05 | 完成后再做下一项 | AC-05：存在活动任务时 next 不返回其他 CLAIM；依赖非 DONE 时不放行 |
| REQ-06 | 架构师判断完成 | AC-06：DONE 缺少匹配审查、合入或验证记录时校验失败 |
| REQ-07 | 审查对应精确版本 | AC-07：审查 SHA 与提交 SHA 不一致时校验失败；新提交需重新审查 |
| REQ-08 | 新功能与变化可追溯 | AC-08：提供变更模板与活动任务重订规格规则，保留旧审查历史 |
| REQ-09 | 异常可恢复 | AC-09：定义冲突、认证失败、阻塞、进程重启及接管行为 |
| REQ-10 | 工具保持运行边界清晰 | AC-10：脚本只读；文档明确外部运行器与身份认证不由本仓库实现 |

## 范围

交付规则、模板、协作需求与设计、校验工具及行为测试。首次不设置生产环境、不创建模型账号、不启用定时后台进程、不接管第三方 Agent 会话。现有仓库为空，因此不预设业务语言、框架、数据库或部署平台。

## 约束与未决项

Git 仓库采用用户提供的 `cason37c/agent_work`。默认一次一个活动任务，保留合并提交与审查历史。实际业务的技术栈、验收环境、模型运行器和托管平台分支保护将随项目需要补充。
