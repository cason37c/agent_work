# CR-0001：独立项目仓库与架构师入口路由

日期：2026-10-24。原规则基线：`67fa7000f72684dc3e057a6e65440ec60ebf0e2b`。

## 原因与期望结果

用户询问多个项目如何管理，并明确要求更新规则。原个人入口默认接续 `agent_work`，协作约定要求文档共用该仓库，README 又允许直接接入业务代码，缺少独立项目和恢复目标的统一约定。

采纳独立项目各用独立仓库：`agent_work` 维护公共规则、工具、项目索引及入口源码；项目的需求、设计、任务、代码与审查放在所属仓库。由架构师准备项目仓库再发布首个编码任务，编码 Agent 按已确认目标实现。

## 影响与兼容

- 更新管理仓库入口、协作约定、架构师及编码规则，并明确单活动任务限制按项目计算。
- 新增 `docs/projects.json` 和多项目管理规则，明确路由、初始化、恢复、归档、规则升级及两仓库写入失败的恢复方式。
- 将个人入口源码纳入版本控制，并同步更新已安装的 `architect` 技能、配置和 UI 提示。
- 当前正式任务队列为空，没有活动任务需要暂停或重新绑定，也无业务代码需要迁移。F0001 需求、设计和原交付检查保留为协作框架历史。
- 现有任务 JSON、工作流脚本和验收门槛继续使用；新增规则不提供自动跨项目调度或远程仓库创建 API。

## 可复核验收

| 编号 | 前提、操作与期望结果 |
| --- | --- |
| MP-01 | 新窗口只启动架构师模式且无匹配目标：读取管理索引并等待需求或选择，不把业务写入管理仓库 |
| MP-02 | 用户提出独立新产品：架构师先准备独立仓库与协作文件，再在该仓库发布任务 |
| MP-03 | 用户给已有项目加功能或说“继续项目 A”：定位该项目并读取其最新规则、队列和审查；同名匹配多个项目时澄清 |
| MP-04 | 两个项目都有 T0001：以仓库地址与任务 ID 共同定位，各项目校验自己的单活动任务限制 |
| MP-05 | 总览、切换或归档：进度从项目仓库读取，索引只保存定位与生命周期；归档保留历史且先处理活动任务 |
| MP-06 | 项目远程已准备但索引推送失败：保留项目成果并明确登记尚未完成，不声称跨仓库原子交接 |
| MP-07 | 更新公共规则和个人入口：旧任务规格保持绑定；已安装入口与版本控制源码一致 |

验证证据记录在 [规则更新检查](../reviews/CR-0001-multi-project.md)；实际创建、恢复及归档业务项目需在首次立项时验证。
